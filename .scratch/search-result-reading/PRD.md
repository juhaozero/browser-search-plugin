# PRD：搜索结果阅读（第一版）

## Problem Statement

在百度和谷歌的桌面版网页搜索结果页上，用户很难一眼看清查询里的词落在哪条结果上，也很难在宽屏上高效浏览结果列表。现有油猴方案功能杂、易随搜索引擎改版整页错位，还夹带广告相关能力。用户需要一个只做阅读辅助的 Chrome 扩展：看清词、按选定列模式排结果条目，并在同一页上接上后续页的结果。

## Solution

做一个 Chrome Manifest V3 扩展。它只作用于桌面版百度和谷歌的网页搜索结果页：把查询拆成高亮段并涂在结果条目的标题和摘要上；把结果条目排成原始模式、单列、单列居中或双列之一；滚到结果列表底部附近时由扩展取下一页结果条目接到后面。偏好在扩展图标弹窗里改，马上作用到已打开的搜索结果页，并跟着 Chrome 账号同步。

## User Stories

1. As a 搜索用户, I want 在桌面版百度网页搜索结果页上自动启用本扩展, so that 我不用再装油猴或手动开脚本。
2. As a 搜索用户, I want 在桌面版谷歌（含常见国家/地区后缀域）网页搜索结果页上自动启用本扩展, so that 换镜像域名也能用。
3. As a 搜索用户, I want 打开百度或谷歌搜索首页时扩展不改页面, so that 只有真正在看结果时才介入。
4. As a 搜索用户, I want 打开图片、视频、资讯、地图、学术等垂类结果时扩展不改页面, so that 不会搞乱那些页面的布局。
5. As a 搜索用户, I want 打开手机版搜索结果页时扩展不改页面, so that 第一版只守桌面版网页搜索。
6. As a 搜索用户, I want 查询按空格和标点拆成高亮段, so that 多词查询里每一段都能单独看清。
7. As a 搜索用户, I want 没有空格的连续中文整段作为高亮段而不再拆开, so that 「浏览器扩展」这类词不会被误拆。
8. As a 搜索用户, I want 不同高亮段用不同底色标出, so that 我能区分查询里的不同段。
9. As a 搜索用户, I want 高亮只出现在结果条目的标题和摘要上, so that 搜索框和页脚杂讯不会被涂花。
10. As a 搜索用户, I want 广告、相关搜索、知识卡上不出现高亮, so that 高亮只服务真正的结果条目。
11. As a 搜索用户, I want 点进结果后的落地页不再继续高亮, so that 扩展不必获得全网权限。
12. As a 搜索用户, I want 弹窗里能开关高亮, so that 偶尔不需要涂色时可以关掉。
13. As a 搜索用户, I want 高亮默认开启, so that 装上就能直接用。
14. As a 搜索用户, I want 自动翻页接上的新结果条目也立刻高亮, so that 后面页和第一页体验一致。
15. As a 搜索用户, I want 在弹窗里四选一选择列模式（原始模式、单列、单列居中、双列）, so that 我能按屏幕宽度挑排法。
16. As a 搜索用户, I want 同一时间只有一种列模式生效, so that 不会叠出混乱布局。
17. As a 搜索用户, I want 默认列模式是单列居中, so that 第一次打开就接近常见脚本的观感。
18. As a 搜索用户, I want 原始模式保持搜索引擎自己的结果排法, so that 我不想改布局时可以一键回去。
19. As a 搜索用户, I want 单列把结果条目排成靠左的一列, so that 我能收窄阅读宽度但不居中。
20. As a 搜索用户, I want 单列居中把结果条目排成居中的一列, so that 视线落在页面中间。
21. As a 搜索用户, I want 双列把结果条目左右并排成两列, so that 宽屏上能一次看到更多条目。
22. As a 搜索用户, I want 列模式只搬动结果条目, so that 搜索框、顶部标签、广告、知识卡、相关搜索留在原地。
23. As a 搜索用户, I want 从双列或单列切回原始模式时结果条目回到打开页面时的位置, so that 「原始」真的是撤销排版。
24. As a 搜索用户, I want 切回原始模式后已接上的下一页结果仍留在列表末尾, so that 不会丢掉已经滚出来的内容。

45. As a 搜索用户, I want 偏好（列模式、高亮开关、自动翻页开关）跟着 Chrome 账号同步, so that 换电脑不用重设。

49. As a 开发者, I want 用「搜索会话」作为唯一高层测试接缝, so that 核心行为可用文档注入验证而不依赖真实浏览器。
50. As a 开发者, I want 取下一页的网络请求放在接缝外, so that 单元测试用注入的下一页文档模拟 ingest。
51. As a 开发者, I want 扩展以 Manifest V3 打包并可本地加载, so that 能在 Chrome 里手动验证百度和谷歌。

## Implementation Decisions

- 交付形态为 Chrome Manifest V3 扩展（见 ADR-0001），不是油猴用户脚本。
- 核心领域逻辑集中在「搜索会话」模块：给定页面文档、当前 URL 与偏好，创建会话；对外暴露判定桌面版网页搜索、拆高亮段、推导下一页 URL、以及对文档施加高亮/列模式/ingest 后续页文档的行为。
- 偏好形状：`columnMode` 为 `original` | `single` | `single-center` | `double`；`highlight` 与 `autoPage` 为布尔值。默认：`single-center`、`true`、`true`。
- 偏好经扩展弹窗读写，存 `chrome.storage.sync`，不可用时退回本机存储；变更通过消息或 storage 事件推到已打开的搜索结果页并立刻重放。
- 内容脚本只匹配桌面版百度与谷歌网页搜索结果页；非匹配页不注入。
- 百度主机：`www.baidu.com`。谷歌主机：`google.com`、`www.google.com` 及带国家/地区后缀的桌面域上的 `/search` 网页结果。
- 列模式非原始时，只把结果条目迁入扩展控制的结果容器并设置模式标记；广告、相关搜索、页码等不迁入。原始模式不创建该容器，并在从其他模式切回时把本页打开时已有的结果条目还原到原始位置。
- 自动翻页：接近结果列表底部时请求下一页 HTML，解析出结果条目后交给会话 `ingest`；以链接去重；连续追加上限 10 页；UI 负责「加载中」「加载失败」提示与滚动重试，不自动连重试。
- 高亮实现细节（DOM 标记类名等）服从外部行为：标题与摘要可见高亮段，搜索框与广告等不可见高亮。
- 构建可用现有 `esbuild` 脚本产出可加载的扩展目录；测试用 Node 内置 test runner + linkedom。

## Testing Decisions

- 只测外部行为，不测内部实现细节（不锁定具体 CSS 选择器实现方式，除非该选择器本身是用户可见契约，如结果容器的模式标记）。
- 唯一高层接缝：搜索会话。优先扩展现有 `test/search-session.test.mjs` 所覆盖的行为。
- 好测试：用 linkedom 构造百度和（必要时空）谷歌结构的文档；断言高亮范围、列模式是否搬走结果条目、页码/相关搜索/广告是否留在原地、ingest 去重与 10 页上限、切回原始模式的还原语义。
- 网络取页、弹窗 DOM、storage 同步视为接缝外；可用手工在 Chrome 加载扩展验证，第一版不强制 E2E 套件。
- Prior art：仓库已有 `test/search-session.test.mjs`，导入 `createSearchSession`、`highlightSegments`、`isDesktopWebSearch`、`nextPageUrl`。

## Out of Scope

- 去广告、去重定向、favicon、结果序号、护眼模式、自定义 CSS、页面内列模式控件
- 跟随查询到落地页的高亮
- 手机版搜索页（如 `m.baidu.com`、谷歌移动版）
- 图片、视频、资讯、地图、学术等垂类结果
- 三列及以上列模式；必应、搜狗及其他引擎
- 谷歌镜像站、自定义搜索（CSE）
- 弹窗内配置自动翻页页数上限
- 发布到 Chrome Web Store（第一版只需可本地加载）
- 把 PRD 发到 GitHub Issues（本仓库用本地 `.scratch/`）
